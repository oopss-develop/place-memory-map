# 우뚜막 전체 백업과 복원

## 내려받기

지도·여행·모아보기에서 ‘전체 백업’을 누릅니다. 사진·이모티콘 포함 상태로 ZIP을 내려받아 컴퓨터와 다른 저장 장치에 각각 보관하세요. 복원은 백업 파일이 있을 때만 가능합니다. 중요한 기록을 추가한 날에 다시 내려받는 것을 권장합니다. 파일은 암호화되지 않으므로 두 분만 접근할 수 있는 곳에 보관하세요.

ZIP에는 접근 가능한 모든 지도, 장소, 기록(휴지통 포함), 참여자, 댓글, 여행·일정, 경로 캐시, 활동 로그, 본인의 즐겨찾기·알림 상태, 사진 원본, 현재 배포된 이모티콘 파일, 백업한 기기의 설정·저장된 초안, DB 스키마 SQL, SHA-256 검증 목록이 들어 있습니다. 다른 사용자의 개인 즐겨찾기·읽음 상태, 로그인 계정의 비밀번호·세션, 초대 토큰, 이미 영구 삭제된 사진, 아직 업로드하지 않은 파일은 포함하지 않습니다. 초안의 사진 파일은 브라우저에 저장되지 않으므로 포함되지 않습니다. 다른 사용자의 개인 상태까지 보관하려면 각자 자기 계정으로 내려받으세요.

‘사진 제외’로 내려받은 파일은 데이터 백업입니다. 사진 메타데이터는 있지만 원본은 없으므로 전체 복원이 불가능합니다. 일부 사진 다운로드가 실패한 경우 완료 파일을 만들지 않습니다. 날짜와 함께 원본이 포함된 최신 ZIP을 보관하세요. 백업 중에는 두 분 모두 기록 수정을 잠시 멈추면 DB 스냅샷과 사진 파일이 더 잘 일치합니다. 사진 URL만 보관하는 방식과 달리 ZIP에 실제 사진이 들어 있습니다.

큰 사진 백업은 PC에서 실행하세요. 브라우저 ZIP 작업은 메모리를 사용하며 파일 전체가 512MB를 넘으면 중단됩니다. 큰 자료는 아래 폴더 백업 도구로 보관할 수 있습니다. ZIP을 풀면 `기록보기.html`에서 네트워크 없이 메모·댓글·사진·일정을 볼 수 있습니다.

## 설치

현재 앱의 마이그레이션을 모두 적용한 다음 `supabase/migrations/202610110001_workspace_backup.sql`을 SQL Editor에서 실행하세요. 이 파일은 반복 실행해도 됩니다. 코드 커밋·푸시 및 재배포도 필요합니다.

## 복원 도구

PC 도구는 Node.js 24 이상과 이 프로젝트의 의존성 설치(`npm ci`)가 필요합니다.

원래 Supabase 프로젝트와 같은 계정 ID를 유지하는 환경에서 복원하는 것이 가장 쉽습니다. 새 프로젝트는 먼저 동일 버전의 앱 스키마와 로그인 계정을 준비하세요. 계정 ID가 달라졌다면 별도의 JSON으로 이전 ID→새 ID를 연결합니다. 계정 생성이나 비밀번호 복원은 자동으로 수행하지 않습니다.

로컬 프로젝트의 `.env.local`에 아래 값을 설정합니다. 관리자 키는 브라우저에 입력하거나 `NEXT_PUBLIC_` 변수로 만들지 마세요.

```text
BACKUP_DATABASE_URL=Supabase에서 제공하는 PostgreSQL 연결 문자열
SUPABASE_SERVICE_ROLE_KEY=Supabase 관리자 키
NEXT_PUBLIC_SUPABASE_URL=https://프로젝트.supabase.co
BACKUP_USER_ID=백업할 사용자 UUID (폴더 백업 시)
```

먼저 검사만 수행합니다. 이 명령은 데이터를 변경하지 않습니다.

```powershell
npm run backup:restore -- --file "D:\Backups\우뚜막-백업.zip"
```

검사 결과를 확인한 뒤 실제 복원합니다.

```powershell
npm run backup:restore -- --file "D:\Backups\우뚜막-백업.zip" --apply
```

ID가 달라졌다면 `--profile-map "D:\Backups\계정연결.json"`도 지정합니다. JSON 형식은 `{"이전-사용자-UUID":"새-사용자-UUID"}`입니다. 소속 지도·장소·기록·사진의 ID는 유지됩니다. 기존 ID가 있는 행과 사진은 덮어쓰지 않습니다. 같은 사진 경로에 다른 내용이 있으면 중단합니다. 기존 행의 내용이 더 최신인 경우 기존 내용이 유지되므로 과거 버전으로 되돌리는 도구는 아닙니다. DB 행은 한 트랜잭션으로 추가하고 사진은 개별 검증·업로드하므로 실패한 복원은 같은 파일로 재실행할 수 있습니다. DB 적용 전에 실패한 사진 업로드는 Storage에 남을 수 있으나 기존 데이터는 변경하지 않습니다. 검증 목록이 다르거나 사진을 제외한 백업은 전체 복원을 차단합니다.

이모티콘 파일은 ZIP의 `stickers/` 아래에 있습니다. 복원 도구는 해당 파일을 지정한 새 출력 폴더로 추출합니다. 검토한 뒤 `public/stickers/`로 옮기고 재배포하세요. 기존 이모티콘 파일을 자동으로 덮어쓰지 않습니다. 기기 설정·초안은 `local-settings.json`에 보관하며 복원 도구에서 자동 적용하지 않습니다. 백업에 포함된 `schema/` SQL은 신규 DB 초기화용입니다. 이미 구성된 DB에 전체 생성 SQL을 다시 실행하지 마세요.

## 큰 백업을 폴더로 보관

```powershell
npm run backup:download -- --out "D:\Backups\우뚜막-2026-10-11"
```

먼저 저장소를 최신 배포 버전으로 갱신하세요. 이 도구의 이모티콘과 스키마는 PC 저장소 파일을 사용합니다.

비어 있는 새 폴더에 데이터·사진·이모티콘을 하나씩 저장합니다. 기기 설정·초안은 브라우저 백업에만 포함됩니다. 폴더도 `backup:restore -- --file "폴더경로"`로 검사·복원합니다. 완료되기 전에는 백업으로 사용하지 마세요. 완료 후 생성되는 `manifest.json`이 검증 목록입니다.
