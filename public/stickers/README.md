# 댓글 이모티콘 관리

`public/stickers/` 바로 아래에 시리즈 폴더를 만들고 PNG, WebP, GIF를 넣으세요.

```text
public/stickers/
  01_우삼/
    01_안녕.png
    02_신나요.gif
    02_신나요.preview.png
  02_뚜냥/
    01_좋아요.webp
```

폴더명은 시리즈 이름, 파일명은 이모티콘 이름입니다. 숫자 접두사(`01_`, `02-`)는 정렬에 사용하고 화면에는 숨깁니다. 루트 파일, 숨김 파일/폴더, 하위 폴더, 지원하지 않는 형식과 `.preview.png` 파일은 목록에서 제외됩니다. GIF의 정지 미리보기는 같은 폴더의 `원본이름.preview.png`입니다. 동작 줄이기를 켠 사용자는 정지 이미지를 보고, 재생 버튼으로 GIF를 재생합니다. 미리보기가 없으면 버튼을 누르기 전에는 GIF를 로드하지 않습니다. 선택 목록에서는 GIF를 자동 재생하지 않습니다.

`npm run dev`와 `npm run build` 전에 목록이 자동 생성됩니다. 개발 서버 실행 중 파일을 수정했다면 `npm run stickers:generate` 후 선택창을 다시 여세요. 목록 파일 `src/generated/stickers.json`은 직접 편집하지 않습니다. 폴더와 파일 변경은 커밋·푸시 및 재배포로 반영됩니다. 빈 시리즈는 표시하지 않습니다.

댓글에는 `01_우삼/01_안녕.png` 같은 상대 경로를 저장합니다. **기존 댓글을 유지하려면 사용 중인 폴더·파일 경로를 유지하세요.** 같은 경로의 파일을 교체하면 기존 댓글에도 반영되며, 내용 해시로 캐시가 갱신됩니다. 폴더나 파일 이름을 바꾸거나 삭제하면 이전 댓글에는 ‘사용할 수 없는 이모티콘’이 표시됩니다. 함께 작성한 텍스트는 유지됩니다. 이모티콘 하나만 보내거나 텍스트와 함께 보낼 수 있습니다.

배포 전에 Supabase SQL Editor에서 `supabase/migrations/202610100002_comment_stickers.sql`을 적용하세요. 초기 댓글 테이블이 없는 DB는 `202610100001_visit_comments.sql`을 먼저 적용하세요. 이후 이모티콘 파일 변경에는 DB 변경이 필요 없습니다. 서버는 생성 목록에 있는 경로만 허용하고 DB는 그룹 권한·본인 삭제·동일 UUID 재전송을 검증합니다. 파일 업로드, 외부 GIF 검색, 대댓글은 지원하지 않습니다.
